# Data schema

This document describes how Korinnia stores data. It is written for future maintainers *and* for anyone who needs to read the archive without the application. It grows with every phase. The authoritative schema is the Alembic migrations in `backend/alembic/versions/`.

## Conventions (all tables)

| Convention | Detail |
|---|---|
| Primary keys | `id UUID`, generated by the application ([D1](decisions.md#d1-uuid-primary-keys-everywhere)) |
| Timestamps | `created_at`, `updated_at` as `timestamptz` (UTC) |
| Soft delete | `deleted_at timestamptz NULL`. Rows are hidden, not removed, until the trash bin is emptied |
| Text | UTF-8 everywhere. Names are stored exactly as entered, in any script |
| Long text | Biographies, stories and notes are Markdown, with no length limit |
| Dates | Partial dates: `year`, `month`, `day`, `date_precision` (plus `*_end` for ranges) ([D2](decisions.md#d2-genealogical-dates-are-not-sql-dates)) |
| Constraint names | Deterministic: `pk_<table>`, `fk_<table>_<column>_<referred table>`, `uq_…`, `ix_…`, `ck_…` |
| Extensions | `unaccent`, `pg_trgm` for case- and accent-insensitive, fuzzy name search |

## Files

Media files are stored as plain files under the media root (`/data/media`). The storage key is the path relative to that root. The original filename, MIME type, size and SHA-256 are recorded in the database (`MediaFile`, phase 6). Originals are never modified. Derived versions (thumbnails, web versions, crops) are separate files.
