# Data schema

This document describes how Korinnia stores data. It is written for future maintainers *and* for anyone who needs to read the archive without the application. It grows with every phase. The authoritative schema is the Alembic migrations in `backend/alembic/versions/`.

## Conventions (all tables)

| Convention | Detail |
|---|---|
| Primary keys | `id UUID`, generated by the application ([D1](decisions.md#d1-uuid-primary-keys-everywhere)) |
| Timestamps | `created_at`, `updated_at` as `timestamptz` (UTC) |
| Soft delete | `deleted_at timestamptz NULL`. Rows are hidden, not removed, until the trash bin is emptied |
| Text | UTF-8 everywhere. Names are stored exactly as entered, in any script |
| Long text | Biographies, stories and notes are Markdown, with no length limit |
| Dates | Partial dates: `year`, `month`, `day`, `date_precision` (plus `*_end` for ranges) ([D2](decisions.md#d2-genealogical-dates-are-not-sql-dates)) |
| Constraint names | Deterministic: `pk_<table>`, `fk_<table>_<column>_<referred table>`, `uq_…`, `ix_…`, `ck_…` |
| Extensions | `unaccent`, `pg_trgm` for case- and accent-insensitive, fuzzy name search |

## Files

Media files are stored as plain files under the media root (`/data/media`). The storage key is the path relative to that root. The original filename, MIME type, size and SHA-256 are recorded in the database (`MediaFile`, phase 6). Originals are never modified. Derived versions (thumbnails, web versions, crops) are separate files.

### Phase 3: genealogical data
All tables below have `tree_id`, `created_by_id`, `updated_by_id`, `created_at`, `updated_at`, and soft-delete columns `deleted_at` + `deleted_batch_id` (rows deleted together share the id of the entity the user deleted).

| Table | Purpose | Key columns |
|---|---|---|
| `persons` | A person | `gender` (`male`/`female`/`other`/`unknown`), `is_living`, `short_summary`, `biography` (Markdown), `occupation`, `education`, `religion`, `nationality`, `notes_for_descendants` (Markdown), `research_status` (`complete`/`partial`/`unknown`), `primary_photo_id` |
| `person_names` | All names of a person | `type` (`birth`/`married`/`nickname`/`alias`/`religious`/`other`), `first_name`, `middle_name`, `patronymic`, `last_name`, `maiden_name`, `script` (`cyrillic`/`latin`/`other`), `is_primary`, `sort_order`, `notes`, `search_text` |
| `places` | A place | `name` (current), `historical_names` (JSON list of `{name, from_year, until_year, note}`), `country`, `region`, `latitude`, `longitude` (WGS84 decimal degrees), `notes`, `search_text` |
| `events` | Life events | `type` (birth, baptism, death, burial, marriage, divorce, education, graduation, military_service, occupation, residence, emigration, immigration, award, illness, custom), `title`, `description` (Markdown), `date_*` (partial date, below), `place_id`, `cemetery_name`, `burial_plot`, `latitude`, `longitude` |
| `event_participants` | Who took part in an event | `event_id`, `person_id` (unique together), `role` (`principal`/`spouse`/`witness`/`godparent`/`officiant`/`other`) |
| `parent_child` | Parent → child link | `parent_id`, `child_id`, `type` (`biological`/`adoptive`/`step`/`foster`/`unknown`), `notes`. One live link per pair |
| `partnerships` | Couple | `person_a_id`, `person_b_id`, `type` (`marriage`/`civil_union`/`partnership`), `start_*` and `end_*` (partial dates), `end_reason` (`divorce`/`death`/`separation`/`other`), `place_id`, `notes` |

Birth and death are rows in `events` (type `birth`/`death`) with one `principal` participant.

#### Partial dates
A date stored with prefix `date_` (or `start_`, `end_`) consists of:

| Column | Meaning |
|---|---|
| `<p>_year`, `<p>_month`, `<p>_day` | Known parts only. A year-only date has no month or day |
| `<p>_precision` | `exact` (Y-M-D), `month` (Y-M), `year`, `approx` (about), `before`, `after`, `between` (range), `unknown` |
| `<p>_end_year`, `<p>_end_month`, `<p>_end_day` | End of the range, only for `between` |
| `<p>_phrase` | Original wording, free text |
| `<p>_sort` | Derived first possible day, for ordering. Not a fact |

Example: "between 1914 and 1918" → `year=1914, precision=between, end_year=1918`.

#### History snapshots (`audit_log.before` / `after` for genealogical entities)
- `person`: all person fields + `names` (list) + `birth`/`death` (`{date, place_id, description}` or null)
- `event`: all fields + `date` + `participants` (`[{person_id, role}]`)
- `parent_child`, `partnership`, `place`: all fields

Dates in snapshots use the column names above without the prefix (`{"year": 1914, "precision": "between", "end_year": 1918, …}`).

| Table | Purpose | Key columns |
|---|---|---|

### Phase 6: media
| Table | Purpose | Key columns |
|---|---|---|
| `media_files` | One uploaded file | `kind` (`photo`/`document_scan`/`audio`/`video`/`pdf`/`other`), `original_key` (path under the media root), `original_filename`, `mime_type`, `size`, `sha256`, `web_key`, `thumb_key` (derived, regenerable), `processing_status` (`pending`/`ready`/`failed`), `processing_error`, `width`, `height`, `duration_seconds`, `title`, `description`, `date_*` (partial date), `place_id`, soft delete |
| `media_persons` | Person in / related to a file | `media_id`, `person_id` (unique together), `region` (`{x,y,w,h}` fractions of the image, or null), `sort_order` (position in the person's gallery) |

New `persons` columns: `primary_photo_id` (FK `media_files`), `primary_photo_crop` (`{x,y,w,h}`), `avatar_key` (derived portrait).

**Reading media without the app:** every original is a plain file at `<media root>/<original_key>`. Its original name, people and description are in `media_files` / `media_persons`, and its integrity can be checked against `sha256`.

### Phase 7: sources, stories and collaboration
| Table | Purpose | Key columns |
|---|---|---|
| `sources` | A document or testimony in the tree's library | `title`, `type` (`civil_record`/`church_record`/`archive_document`/`census`/`newspaper`/`letter`/`oral_history`/`book`/…), `author`, `archive_name`, `reference_number`, `url`, `notes`, `search_text` (transliterated, trigram index), soft delete |
| `source_media` | Scans attached to a source | `source_id`, `media_id` |
| `citations` | "This fact is supported by that source" | `source_id`, `entity_type` (`person`/`person_name`/`event`/`parent_child`/`partnership`/`media`), `entity_id`, `field` (e.g. `occupation`, only for `person`), `page`, `quality` (`primary`/`secondary`/`family_tradition`/`unverified`), `notes`, soft delete |
| `stories` | A story or memory (Markdown) | `title`, `body`, `narrator`, `date_*` (partial date), `status` (`draft`/`pending_review`/`published`), `author_user_id`, `review_comment`, soft delete |
| `story_persons` / `story_media` | People a story is about; media it shows | `story_id` + `person_id` / `media_id` |
| `edit_suggestions` | A contributor's proposed change | `entity_type` (`person`/`event`), `entity_id`, `patch` (JSON: field → proposed value), `comment` (where the information comes from), `status` (`pending`/`approved`/`rejected`), `created_by_id`, `reviewed_by_id`, `reviewed_at`, `review_comment` |
| `comments` | Discussion | `entity_type` (`person`/`story`/`media`), `entity_id`, `body`, `author_id`, `deleted_at` |
| `open_questions` | Research to-dos per person | `person_id`, `question`, `notes`, `status` (`open`/`resolved`), `resolution`, `resolved_at`, `created_by_id` |

`citations`, `comments` and `edit_suggestions` point at their target with a plain (`entity_type`, `entity_id`) pair rather than a foreign key, so one table covers every kind of fact. The service checks that the target exists in the same tree.

### Phase 8: insights
No new tables. The timeline, map, "on this day", relationship calculator and statistics are computed from the tables above when requested.

### Phase 9: GEDCOM import and integrity checks
| Table | Purpose | Key columns |
|---|---|---|
| `gedcom_imports` | One uploaded GEDCOM file and what happened to it | `tree_id`, `created_by_id`, `status` (`analyzing`/`ready`/`importing`/`done`/`failed`/`undoing`/`undone`/`cancelled`), `file_key` (the original file, kept in storage under `imports/`), `filename`, `size`, `sha256`, `preview` (JSON: counts, warnings, people, duplicate candidates), `decisions` (JSON: `merge` = GEDCOM xref → existing person id), `result` (JSON: counts, skipped items, ids of everything created), `error`, `finished_at` |
| `integrity_runs` | One pass over all stored originals | `status` (`running`/`done`/`failed`), `trigger` (`scheduled`/`manual`), `triggered_by_id`, `started_at`, `finished_at`, `files_checked`, `bytes_checked`, `problems`, `untracked_files`, `error` |
| `integrity_issues` | An original that failed its check | `run_id`, `media_id`, `tree_id`, `key`, `problem` (`missing`/`size_mismatch`/`hash_mismatch`/`unreadable`), `expected_size`, `actual_size`, `expected_sha256`, `actual_sha256` |

Imported people, events, places, sources and citations are ordinary rows of the tables above (created through the same services, with revisions and audit entries); `gedcom_imports.result` only remembers their ids for "undo import".

### Phase 10: share links
| Table | Purpose | Key columns |
|---|---|---|
| `share_links` | A read-only link to one tree for people without an account | `tree_id`, `token_hash` (SHA-256 of the token in the URL; the token is shown once), `label`, `created_by_id`, `created_at`, `expires_at` (null: no expiry), `revoked_at`, `last_used_at`, `use_count` |

`users` also gained `welcome_dismissed`, `changelog_seen` and `show_changelog` (migration 0009, D95).
